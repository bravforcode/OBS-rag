## 3. Efficiency Tooling: RTK vs. The World
RTK represents a unique "Pre-Injection" compression layer that is currently superior for CLI-heavy engineering compared to standard prompt compression.

*   **RTK (The Surgeon)**: Operates at the shell level. It prunes 60-90% of noise (boilerplate, whitespace, redundant logs) *before* the LLM sees it. This is critical for keeping costs low and preventing "attention drift" in the model.
*   **Prompt Compression (The Strategist)**: Tools like `LLMLingua` or `semantic-summarizers` work on the conversation history. They are better for long-term memory but often fail to handle the high-velocity "spam" of build tools.

**Strategic Positioning**: Use RTK as the mandatory CLI proxy to preserve the primary context window for logic, while using RUFLOW-style memory for persistent project state.

## 4. Architectural Standard: Progressive Disclosure
Consistency across agents (Claude, Gemini, Codex) is best achieved via a **Path-Scoped Rule Hierarchy**.

1.  **Level 0 (Global)**: `~/.gemini/gemini.md` - Core personality and safety constitutional rules.
2.  **Level 1 (Project Root)**: `CLAUDE.md` + `GEMINI.md` - High-level "Map" (Stack, Build, Test, Architecture).
3.  **Level 2 (Scoped)**: `.claude/rules/*.md` - JIT rules that load only for relevant paths (e.g., UI rules only in `src/components`).

**Authority Tip**: Do NOT use a single 1000-line rule file. It causes "Rule Fatigue" where the agent begins to ignore instructions at the end of the file.

## 5. Multi-Agent Orchestration Protocols
To scale engineering without chaos, implement the following:
*   **PEC (Planner-Executor-Critic)**: Never let an agent write code without a separate "Critic" agent verifying against `.clauderules`.
*   **Blast Radius Gating**: Tasks affecting >3 files require an explicit "Implementation Plan" phase (Writing-Plans skill) before execution.
*   **TDD-Absolute**: All agents must verify logic with tests before marking tasks as complete.
